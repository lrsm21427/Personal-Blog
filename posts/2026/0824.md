# 海康 USB 门禁读卡器开发与前端集成

门禁系统录入人员 IC 卡时，浏览器无法直接稳定调用海康原生 USB SDK。本文以海康 USB 读卡器为例，介绍一套可落地的集成方式：由`本机读卡服务`封装原生 SDK，再通过本地 HTTP 接口向 Vue 前端提供设备检测和读卡能力，最后把卡号绑定到 OA 门禁人员档案。

本文示例使用海康 `DS-K1F100A-D8E` USB 读卡器，实际设备和 SDK 版本应以项目现场为准。

## 一、整体架构

```text
海康 USB 读卡器
      ↓ 原生 USB SDK
Windows 本机读卡服务（127.0.0.1:18080）
      ↓ HTTP/JSON
Vue 前端 CardReaderDialog
      ↓ PUT /access/person/bind-ic
OA 门禁后端 → 人员档案 / Redis / 海康同步链路
```

这样设计的原因：

- 浏览器不能直接加载 DLL 或调用厂商原生 SDK；
- USB 设备只需要在操作员电脑上访问，不应经过业务服务器；
- 前端只依赖稳定的 JSON 协议，不关心 SDK 语言和底层函数；
- 本机服务可以统一处理设备枚举、超时、并发和错误码。

## 二、下载海康 USB SDK

官方地址：[海康开放平台 USB SDK 下载](https://open.hikvision.com/download/5cda567cf47ae80dd41a54b3?id=cd699e0e3def4519a6e8676f72e1ea1e&type=20)。

页面提供 Windows、Linux、Android、iOS 等平台版本。Windows 项目应根据本机服务的进程架构选择 `Win32` 或 `Win64`，不能只根据操作系统位数判断。

![海康开放平台 USB SDK 下载页面](/images/posts/hik-card-reader/01-usb-sdk-download.png)

下载并解压后，重点检查：

- 开发指南和 API 说明；
- 对应架构的动态库及依赖文件；
- C、C++、C# 或 Java Demo；
- 设备驱动、运行库和错误码说明；
- SDK 支持的设备型号和固件要求。

> 厂商 SDK 的函数名、结构体和返回码可能随版本变化。原生层实现应以下载包内同版本头文件、Demo 和开发指南为准，不要混用其他版本示例。

## 三、环境准备

#### 1. 硬件与系统

- 海康 USB 读卡器；
- 支持的 IC 卡，例如 Type-A M1 卡；
- Windows 10/11；
- 与应用架构匹配的 USB SDK；
- Microsoft Visual C++ 运行库（具体版本以 SDK 说明为准）。

#### 2. 设备检查

连接设备后，先在 Windows 设备管理器中确认设备能够正常识别，再运行 SDK 自带 Demo。只有官方 Demo 能稳定检测设备和读取 UID 后，才开始封装本机服务。

推荐排查顺序：

```text
USB 连接 → 系统识别 → 官方 Demo → 本机服务 → REST 接口 → Vue 页面 → OA 绑定
```

## 四、本机读卡服务设计

本机服务监听：

```text
http://127.0.0.1:18080
```

服务只绑定回环地址，不监听局域网网卡。核心职责包括：

1. 初始化和释放海康 USB SDK；
2. 枚举并选择支持的读卡器；
3. 读取卡片 UID；
4. 将 UID 统一转换为十六进制和十进制卡号；
5. 对浏览器提供简单、稳定的 HTTP 接口；
6. 处理 CORS、超时、并发读取和设备断开。

原生 SDK 调用流程可以抽象为：

```text
加载 SDK
  → 初始化
  → 枚举 USB 设备
  → 打开目标读卡器
  → 等待并读取卡片 UID
  → 转换卡号
  → 关闭设备
  → 释放 SDK
```

> 上述为通用流程，不是具体 SDK 函数名。实际函数和参数必须以当前下载包为准。

## 五、本机服务接口

### 1. 查询设备状态

```http
GET /api/status
```

设备已连接：

```json
{
  "success": true,
  "connected": true,
  "message": "读卡器已连接",
  "device": {
    "name": "USB Reader",
    "serialNumber": "已脱敏",
    "vid": 0,
    "pid": 0
  }
}
```

设备未连接：

```json
{
  "success": true,
  "connected": false,
  "message": "未检测到 USB 读卡器"
}
```

### 2. 读取卡片

```http
POST /api/read-card
```

成功响应：

```json
{
  "success": true,
  "uidHex": "01020304",
  "uidDecimal": "16909060",
  "uidLength": 4,
  "cardType": "Type-A M1卡",
  "readAt": "2026-08-24T10:00:00+08:00",
  "device": {
    "name": "USB Reader",
    "serialNumber": "已脱敏",
    "vid": 0,
    "pid": 0
  }
}
```

接口建议在 5 秒内等待一次卡片。超时、设备断开或 SDK 读取失败时，应返回非 `2xx` 状态和可读错误信息：

```json
{
  "success": false,
  "message": "读取超时，请将卡片放在读卡区域"
}
```

### 3. 跨域与安全响应头

前端页面与本机服务端口不同，属于跨域请求。本机服务至少应允许业务站点使用：

```http
Access-Control-Allow-Origin: https://oa.example.com
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
Cache-Control: no-store
```

不要在生产环境无条件返回 `Access-Control-Allow-Origin: *`。还应校验 `Origin`，限制请求方法和路径，避免任意网站调用本机读卡器。

## 六、UID 与十进制卡号转换

读卡器通常返回字节数组或十六进制 UID，而业务系统可能保存十进制卡号。示例中：

```text
十六进制 UID：01020304
十进制卡号：16909060
```

Java 转换示例：

```java
import java.math.BigInteger;

String uidHex = "01020304";
String uidDecimal = new BigInteger(uidHex, 16).toString(10);
```

前端 TypeScript 转换示例：

```ts
const uidDecimal = BigInt(`0x${uidHex}`).toString(10)
```

需要特别确认字节序。部分设备或旧系统会反转 UID 字节，如果读卡结果需要与既有卡库、海康平台或门禁控制器匹配，必须使用同一转换规则，并通过多张已知卡片做对照测试。

## 七、Vue 前端接口封装

本项目通过环境变量配置本机服务地址，默认使用 `127.0.0.1:18080`：

```properties
VITE_CARD_READER_URL=http://127.0.0.1:18080
```

接口类型：

```ts
export interface CardReaderDevice {
  name: string
  serialNumber: string
  vid: number
  pid: number
}

export interface CardReaderStatus {
  success: boolean
  connected: boolean
  message: string
  device?: CardReaderDevice
}

export interface CardReadResult {
  success: boolean
  uidHex: string
  uidDecimal: string
  uidLength: number
  cardType: string
  readAt: string
  device: CardReaderDevice
}
```

请求封装：

```ts
const CARD_READER_BASE_URL = (
  import.meta.env.VITE_CARD_READER_URL || 'http://127.0.0.1:18080'
).replace(/\/$/, '')

export const CardReaderApi = {
  getStatus: () => requestLocal<CardReaderStatus>('/api/status', undefined, 3000),
  readCard: () =>
    requestLocal<CardReadResult>('/api/read-card', { method: 'POST' }, 8000)
}
```

`requestLocal`应使用`AbortController`设置超时，并将网络错误转换为明确提示：

```text
连接本地读卡服务超时
本地读卡服务未启动，请先运行“海康 IC 读卡器”
```

## 八、读卡弹窗组件

`CardReaderDialog`打开后先调用状态接口，设备可用时才允许读卡：

```ts
const checkStatus = async () => {
  const result = await CardReaderApi.getStatus()
  serviceReachable.value = true
  deviceConnected.value = result.connected
  device.value = result.device
}

const readCard = async () => {
  const result = await CardReaderApi.readCard()
  cardNo.value = result.uidDecimal
  device.value = result.device
  hasReadCard.value = true
}
```

交互上需要区分三种状态：

- 本机服务未启动；
- 本机服务正常，但未连接读卡器；
- 读卡器已连接，可以读取。

再次读卡前应提示用户先移开上一张卡，防止设备连续返回同一个 UID。

## 九、前端集成测试页

在接入 OA 业务页面前，建议先使用独立测试页验证本机服务。测试页应展示：

- 本机服务和设备连接状态；
- 手动重新检测；
- 读取按钮和操作提示；
- 十六进制 UID、十进制卡号、卡片类型、UID 长度；
- 读取时间和当前设备信息。

![海康 USB 读卡器前端集成测试页（敏感数据已打码）](/images/posts/hik-card-reader/02-reader-test-redacted.png)

测试页只用于本机联调，不应把卡号、UID 或设备序列号上传到第三方服务。

## 十、绑定 OA 门禁人员

人员列表通过读卡弹窗取得十进制卡号，然后调用业务后端：

```ts
const bindIc = async (row: AccessPersonVO) => {
  const value = await cardReaderDialogRef.value?.open(row.icNo || '')
  if (!value) return
  await AccessPersonApi.bindIc(row.id!, value)
  await getList()
}
```

前端业务接口：

```http
PUT /access/person/bind-ic?personId={personId}&icNo={uidDecimal}
```

后端接口需要`access:person:update`权限。绑定完成后：

- 保存人员的`icNo`；
- 已采集人脸时，将授权状态设为`ACTIVE`；
- 未采集人脸时，将状态设为`PENDING_FACE`；
- 刷新 Redis 中的门禁人员缓存；
- 后续可通过人员同步链路下发海康门禁系统。

建议后端进一步增加卡号格式校验和唯一性约束，避免同一张卡绑定给多个人员。

## 十一、联调检查清单

### SDK 与设备

- SDK 架构与本机服务进程一致；
- 官方 Demo 可以检测设备并读取同一张卡；
- 动态库和运行库已随程序正确发布；
- 拔插设备后可以重新检测或自动恢复；
- 同一张卡多次读取结果一致。

### 本机服务

- 只监听`127.0.0.1`；
- `/api/status`可区分服务、设备状态；
- `/api/read-card`具备超时和并发保护；
- 只允许可信业务站点跨域访问；
- 日志不记录完整卡号和设备序列号；
- 服务退出时正确关闭设备并释放 SDK。

### 前端与业务后端

- 页面打开时自动检测服务；
- 未连接设备时禁用读卡按钮；
- 网络超时和 SDK 错误有明确提示；
- 只提交十进制数字卡号；
- 绑定成功后刷新人员列表；
- 后端校验人员存在、权限和卡号唯一性；
- HTTPS 业务站点已验证浏览器对本机 HTTP 和本地网络访问的安全策略。

## 十二、常见问题

| 问题 | 常见原因 | 处理方法 |
| --- | --- | --- |
| 官方 Demo 找不到设备 | 驱动、USB 线、设备型号或权限问题 | 更换 USB 口，检查设备管理器和 SDK 支持列表 |
| 本机服务启动失败 | DLL 缺失或 x86/x64 不匹配 | 检查依赖目录、进程架构和 VC++ 运行库 |
| 前端提示服务未启动 | 端口错误、进程未运行或被安全软件拦截 | 检查 `127.0.0.1:18080/api/status` |
| 浏览器跨域失败 | CORS 或 OPTIONS 未处理 | 配置允许的 Origin、Method 和 Header |
| 读取一直超时 | 卡片类型不支持或读卡区域不正确 | 用官方 Demo 复测，确认卡片制式 |
| 卡号与旧系统不一致 | UID 字节序或进制转换不同 | 固化转换规则，并用已知卡片对照 |
| 连续读取同一张卡 | 卡片未移开或 SDK 重复上报 | 增加移卡提示和短时间去重 |
| HTTPS 页面调用失败 | 浏览器混合内容或本地网络访问策略 | 评估本机 HTTPS、可信证书或浏览器策略配置 |

## 十三、安全注意事项

- 卡号属于门禁凭证数据，日志、截图和监控中应脱敏；
- 本机服务不得监听`0.0.0.0`并暴露到局域网；
- 不接受任意 Origin，不提供通用 USB 操作接口；
- 不允许网页传入 DLL 路径、设备句柄或任意原生参数；
- 对读卡接口做串行化或互斥控制；
- 安装包、SDK 动态库和本机服务应校验来源与完整性；
- 业务后端应记录绑定操作审计，但避免记录完整卡号。

## 十四、总结

海康 USB 读卡器的推荐集成链路是：

```text
官方 SDK 与 Demo 验证
→ 本机服务封装原生 SDK
→ /api/status 检测设备
→ /api/read-card 读取并转换 UID
→ Vue 弹窗获取十进制卡号
→ OA 后端绑定人员并进入海康同步链路
```

这种方式隔离了浏览器与原生 SDK，既方便前端集成，也便于控制设备权限、升级 SDK 和排查现场问题。
